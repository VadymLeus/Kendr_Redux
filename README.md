# Kendr Redux

Реінженіринг NoCode-платформи конструювання вебресурсів Kendr (React.js + Node.js + MySQL) у межах курсової роботи з дисципліни «Розробка та реінженірінг програмних систем».

> Цей репозиторій — окремий проєкт реінженірингу. Вихідна система (кваліфікаційна робота бакалавра) залишається без змін у власному репозиторії: **[VadymLeus/Kendr](https://github.com/VadymLeus/Kendr)**. Її код зафіксовано на коміті `1fb606f`, який у цьому репозиторії позначено тегом `v0` як точку відліку (baseline).

## Про вихідну систему

Kendr — веборієнтована NoCode-платформа, що дозволяє створювати адаптивні вебсайти та інтернет-магазини без програмування. Структура сторінок зберігається у форматі JSON (Schema-Driven UI), а сайт збирається з готових блоків у візуальному drag-and-drop редакторі.

Можливості вихідної версії:

- візуальний редактор сторінок із набором функціональних блоків, шаблонами та експортом сайту;
- інтернет-магазин: товари, категорії, кошик, замовлення, оплата через LiqPay, доставка «Нова Пошта»;
- медіатека (Cloudinary), форми зворотного зв'язку, аналітика відвідувань;
- ролі (гість, користувач, модератор, адміністратор), команда співавторів сайту, тарифні плани;
- система підтримки: тікети, скарги, апеляції;
- автентифікація через JWT та Google OAuth, двофакторна перевірка, Cloudflare Turnstile.

## Мета реінженірингу

Усунути архітектурні проблеми, що накопичилися за час розробки, зберігши функціональність платформи, а результат підтвердити автоматизованими тестами та метриками «до/після».

## Напрями реінженірингу

| № | Напрям | Проблема у вихідній версії (`v0`) | Ціль |
|---|--------|-----------------------------------|------|
| 1 | Редактор блоків | Логіка одного блока розкидана по кількох місцях (реєстрація, значення за замовчуванням, налаштування, каталог, рендер, експорт); експорт сайту фактично містить другий рендерер | Єдиний реєстр блоків: один дескриптор на блок |
| 2 | Архітектура backend | SQL-запити у більшості контролерів, відсутній сервісний шар, дублювання запитів і логіки, неповні моделі | Шарова архітектура: routes → controllers → services → repositories |
| 3 | Узгодженість бізнес-правил | Обчислення цін, тарифні ліміти, права співавторів та перевірки доступу розходяться між клієнтом і сервером | Єдині серверні політики (ціноутворення, тарифи, доступ) та спільна валідація |
| 4 | Тестування | Мінімальне покриття, backend без тестів | Характеризаційні тести перед рефакторингом, далі unit/інтеграційні/e2e |

Детальний реєстр дефектів і обґрунтування вибору напрямів — у [`docs/02-analysis`](docs/02-analysis).

## Технологічний стек

- **Frontend:** React, Vite, Tailwind CSS, React DnD, Axios
- **Backend:** Node.js, Express.js, MySQL 8, JWT, Passport (Google OAuth)
- **Зовнішні сервіси:** Cloudinary, LiqPay, Resend, Cloudflare Turnstile, «Нова Пошта»
- **Тестування:** Vitest (unit/інтеграційні), Playwright (e2e)

## Запуск

### Вимоги

- Node.js 20 LTS або новіший
- MySQL 8.0

### База даних

```sql
CREATE DATABASE KendrDB;
```

Імпортуйте структуру таблиць зі скрипта `db/schema.sql`.

### Backend

Файл змінних середовища створюється копіюванням шаблону:

```bash
cd backend
cp .env.example .env                # Linux, macOS
# Copy-Item .env.example .env       # Windows PowerShell
```

Заповніть значення в `.env`. Обов'язкові змінні: `DB_*`, `JWT_SECRET` та `ENCRYPTION_KEY` (рівно 32 символи). Ключі зовнішніх сервісів потрібні лише для відповідного функціоналу (оплата, медіатека, пошта, вхід через Google, капча, доставка).

Далі встановіть залежності й запустіть сервер:

```bash
npm install
npm run dev
```

Сервер доступний за адресою `http://localhost:5000`.

### Frontend

```bash
cd frontend
cp .env.example .env                # Linux, macOS
# Copy-Item .env.example .env       # Windows PowerShell
npm install
npm run dev
```

Клієнт доступний за адресою `http://localhost:5173`.

### Тести

```bash
cd frontend
npm run test          # unit та інтеграційні
npx playwright test   # e2e
```

Тестів backend у `v0` немає. Характеризаційні тести (Vitest, supertest) працюють із тестовою MySQL у Docker, окремою від робочої БД:

```bash
docker compose up -d                  # MySQL 8 на порту 3307; дочекайтеся статусу healthy
cd backend
npm install --legacy-peer-deps
npm test
```

Опис тестів, захисту від запуску на робочій БД і зв'язок із реєстром дефектів — у [`backend/tests/README.md`](backend/tests/README.md).

## Робочий процес

- `main` — стабільна лінія; кожен напрям реінженірингу розробляється у власній гілці (`test/characterization`, `refactor/block-registry`, `refactor/service-layer`, `fix/policies`) і зливається через pull request.
- В описі кожного PR зазначаються змінені модулі, метрики до/після та додані тести.
- Повідомлення комітів — у форматі Conventional Commits (`refactor:`, `fix:`, `test:`, `docs:`).
