# ADR-002: Єдиний реєстр блоків редактора

- Статус: запропоновано
- Дата: 11.10.2026
- Версія: v1.0
- Пов'язані дефекти: D-xx (розмазана логіка блока), D-xx (цикл BlockRenderer ↔ LayoutBlock), D-xx (дублювання рендера в експорті)

## Контекст
Опис одного типу блока розкидано по шести місцях у п'яти файлах:
- `BlockRenderer.jsx` — `blockMap` (відповідність типу компоненту);
- `editorConfig.jsx` — `BLOCK_LIBRARY` (каталог) і `getDefaultBlockData` (значення за замовчуванням);
- `SettingsTab.jsx` — `SettingsComponentMap` (панель налаштувань);
- `AddBlocksTab.jsx` — жорстко задані списки типів у фільтрах категорій;
- `htmlGenerator.js` — `switch` за типом для експорту сайту.

Додатково: у `BlockSettingsModal.jsx` лежить другий, мертвий `SettingsComponentMap`. Експорт сайту фактично є другим рендерером: блоки «Каталог» та «Вітрина» там замінено заглушками. Одинадцять блоків обгорнуто в `React.memo` зі порівнянням через `JSON.stringify`. `madge` знаходить два цикли залежностей навколо `BlockRenderer` ↔ `LayoutBlock` (див. `metrics-before.md`).

## Рішення
Ввести реєстр, де кожен тип блока описується одним дескриптором:

```js
registry.hero = {
  type: 'hero',
  label: 'Обкладинка',
  icon: Image,
  category: 'basic',                       // замість жорстких списків у AddBlocksTab
  getDefaults: (options) => ({ ... }),     // замість getDefaultBlockData
  Component: lazy(() => import('./Hero/HeroBlock')),
  Settings:  lazy(() => import('./Hero/HeroSettings')),
  toHtml: (data, ctx) => '...',            // замість switch у htmlGenerator
};
```

`BlockRenderer`, `SettingsTab`, `AddBlocksTab`, `getDefaultBlockData` та `htmlGenerator` читають дані лише з реєстру. `BLOCK_LIBRARY` стає похідним від реєстру. Один спільний компаратор `areBlockPropsEqual` замінює п'ять-одинадцять копій порівняння через `JSON.stringify`. Вкладений блок `Layout` отримує рендерер дочірніх блоків як залежність (проп або контекст), а не імпортом, що має прибрати цикли; результат перевіряємо `madge`.

## Розглянуті альтернативи
- Залишити як є й документувати шість місць — не усуває причину помилок при додаванні блока.
- Генерувати реєстр кодогенерацією зі структури папок — зайва складність для 14 блоків.

## Наслідки
- Додавання блока: 2 нових файли і один запис у реєстрі замість правок у 6 місцях.
- Поведінка експорту в `v1.0` не змінюється (заглушки каталогу лишаються), їх заміна — окреме рішення.
- Ризик: ліниве завантаження може змінити порядок ініціалізації; закривається тестами рендера (ADR-005).

## Як перевіряємо
- Ручний підрахунок «місць для змін при додаванні блока»: до — 6, після — 1.
- `madge --circular`: до — 2, ціль — 0.
- Тести: усі типи блоків рендеряться з дефолтними даними, результат експорту збігається з еталоном `v0`.
