# ADR-003: Шарова архітектура backend

- Статус: запропоновано
- Дата: 11.10.2026
- Версія: v1.0
- Пов'язані дефекти: D-ARC-01 (SQL у контролерах), D-ARC-02 (немає моделей), D-ARC-03 (ручні транзакції), D-ARC-05 (повторення запитів у `pageController`), D-ARC-08 (функції-велетні в контролерах `site` і `order`)

## Контекст
За каталогом API та `metrics-before.md`:
- 14 із 21 контролера виконують SQL безпосередньо (196 викликів), найбільше в `adminController` (43), `teamController` (30), `orderController` (29), `siteController` (28);
- шість контролерів не мають моделей (`delivery`, `media`, `order`, `report`, `team`, `transaction`), п'ять із них пишуть SQL самі;
- транзакції відкриваються вручну в дев'яти місцях: сім у контролерах, дві в моделях.

У дипломі (рис. 2.5) заявлено ланцюжок «контролер → модель → БД», що не відповідає коду.

## Рішення
Ввести шари:

```
routes/        шлях, middleware
controllers/   лише HTTP: розбір запиту, виклик сервісу, формування відповіді
services/      бізнес-правила (OrderService, SiteService, PageService, ProductService, PricingService, PlanPolicy)
repositories/  увесь SQL (OrderRepository, ProductRepository, SiteRepository, PageRepository)
config/db.js   пул з'єднань (наявний файл) і withTransaction(fn) — єдина обгортка транзакції
```

Наявні моделі `Site`, `Product`, `Page` поступово перетворюються на репозиторії (перейменування та перенесення), а не живуть паралельно.

Обсяг робіт — вертикальний зріз: контролери `order`, `site`, `page`, `product`. Разом це 66 із 196 прямих SQL-викликів (29 + 28 + 6 + 3). Решта контролерів (`admin`, `team`, `auth` та інші) виходять за межі курсової й описуються в перспективах.

## Розглянуті альтернативи
- ORM (Sequelize, Prisma): потребує переписування всіх запитів і опису 28 таблиць, що не вкладається в обсяг роботи; змішування ORM і сирого SQL ускладнить код.
- Залишити моделі та додати лише сервіси: SQL залишиться у двох шарах одночасно.

## Наслідки
- Контролери зрізу стають тонкими, логіка тестується без HTTP.
- Тимчасово в проєкті співіснують два стилі (зріз і решта контролерів).

## Як перевіряємо
- Контролери з прямими SQL: 14 → 10; прямих викликів: 196 → 130.
- Ручних відкриттів транзакції в зрізі: 0 (усе через `withTransaction`).
- Характеризаційні тести (ADR-005) проходять без змін.
